# 完善全链路监控（端到端可观测性）

现状：监控栈已建 ~70%，但「全链路」在 6 处断点。方案分 4 阶段、**flag/config 门控、零回归**（缺省行为不变），各阶段可独立合入。本环境 **Docker 不可用**，验证为「配置校验 + 单测/构建级」，不跑 live compose。

---

## 阶段 1 — 链路贯通（端到端 tracing）★核心
现状：Python span 已生成但导出到 `:4318` **无后端接收**；Python→Java **无 traceparent 传播**；Java **完全未接 tracing**。

1. **加 tracing 后端**（`deploy/docker-compose.yml` + `deploy/docker-compose.demo.yml`）：新增 `jaeger`（`jaegertracing/all-in-one`，`COLLECTOR_OTLP_ENABLED=true`，暴露 UI `16686`、OTLP-http `4318`），挂 `smartcs-net`；bot/assist/mcp-server 注入 `JAEGER_HOST=jaeger`。
2. **Python→Java 传播**：`shared/tracing.py::instrument_app` 增加 `HTTPXClientInstrumentor().instrument()`（gated），使 MCP streamable-http 每次 POST 自动带 W3C `traceparent`；`mcp_client.py::call_tool` 包一层 `@traced("MCP.call_tool")` 作为客户端父 span。新增依赖 `opentelemetry-instrumentation-httpx`（`pyproject.toml`）。
3. **Java 入站**：`mcp-server/pom.xml` 加 `micrometer-tracing-bridge-otel` + `opentelemetry-exporter-otlp`；`application.yml` 配 `management.tracing.sampling.probability`（prod 低采样）、`management.otlp.tracing.endpoint`。Spring Boot Observation 自动抽取入站 `traceparent` 建 server span → Python 客户端 span 与 Java span 串成一条链。
4. `.env.example`：补 `SMARTCS_TRACING_ENABLED`、`JAEGER_HOST`、Java `MANAGEMENT_OTLP_TRACING_ENDPOINT`、采样率（默认值 = 现状）。

## 阶段 2 — 指标补全 + 采集/看板修复
现状：Java Micrometer **未被采集**；Grafana `smartcs-overview.json` 引用 ~7 个**代码里不存在**的指标 → 面板空。

5. `config/prometheus.yml`：新增 job `mcp-server`，`metrics_path=/actuator/prometheus`，target `host.docker.internal:8090`（与 bot/assist 一致的宿主机约定）。
6. **补指标**（`shared/metrics.py`，沿用现有 `_MockMetric` 容错模式）：
   - `llm_call_duration_seconds`（Histogram，`llm.py` 的 `chat`/`chat_with_tools` 计时）；
   - `smartcs_fast_reply_total`、`smartcs_agent_responses_total`（Counter）、`smartcs_bot_semaphore_utilization`、`smartcs_active_workers`、`smartcs_stream_length`、`smartcs_stream_pending_total`（Gauge）——在 bot 信号量/流 worker/router 的自然埋点处递增；无法干净映射的改为**修正看板查询**指向真实指标，避免为凑指标改热路径。
7. `config/grafana/dashboards/smartcs-overview.json`：所有 PromQL 对齐最终指标名；补 Java `mcp_tool_calls_total`/`mcp_tool_call_duration` 面板。

## 阶段 3 — 日志↔链路关联
现状：两端日志都不带 trace_id；`get_trace_id()` 已定义但**从未调用**；Java MDC 未渲染。

8. **Python**：`shared/logger.py` 新增 `TraceContextFilter`，把 `trace_id`/`span_id` 注入 `JSONFormatter`（调用现成 `get_trace_id()` + span_id）；无活跃 span 时省略字段，tracing 关时零开销。
9. **Java**：`mcp-server/src/main/resources/logback-spring.xml`，日志 pattern 含 `[%X{traceId:-},%X{spanId:-}]`（micrometer-tracing 自动填 MDC）。

## 阶段 4 — 告警 + 可观测性测试
现状：无告警规则/Alertmanager；`test_metrics.py` 实为 RAG 评测，无监控断言。

10. `config/prometheus/rules/alerts.yml` + `prometheus.yml` 加 `rule_files`：服务下线、工具错误率高、LLM 延迟 p99、会话超时激增、降级触发。Alertmanager 作为**可选 opt-in** compose 服务（默认不拉起）。
11. **测试**：
   - `agent/tests/test_observability.py`：`/metrics` 返回关键指标名；`PrometheusMiddleware` 计数；`@traced`/`get_trace_id`/`TraceContextFilter` 行为；`HTTPX` 注入 traceparent（用 in-memory span exporter 断言）。
   - Java `ToolCallAspectTest`（`SimpleMeterRegistry` 断言 `mcp_tool_calls_total` 发射）。
   - 一个轻量一致性测试：校验 dashboard JSON 里的指标名都在代码中定义（防再次漂移）。
